# Security Policy

This project is pre-release. Report suspected vulnerabilities privately to the
repository owner; do not include health data, access tokens, credentials, or
proof-of-concept data from another person in an issue.

This standalone repository does not have a remote or staffed disclosure address
yet. Before any public deployment, the owner must enable GitHub private
vulnerability reporting (or publish a monitored security address here) and test
that route. Until then, this missing channel is a launch blocker—not permission
to file sensitive details publicly.

The application must treat food diaries, biometrics, integration tokens, exports,
and free-text notes as sensitive. Security reports are acknowledged and triaged
before feature work. No public vulnerability bounty or response-time promise is
made until a staffed disclosure process exists.
